# 🤖 Job Application Engine

A database-driven, multi-site job application automation engine built on the **Strategy Pattern**. Each job board has its own self-contained strategy module. Configuration, deduplication, and audit logging all live in a single DuckDB file.

---

## 🏗️ Architecture

```
scripts/main.py                   ← Single-site manual entry point
scripts/scheduler_worker.py       ← Scheduled multi-site runner

engine/
  ├── runner.py                   ← Orchestrates browser + strategy per site
  ├── factory.py                  ← Dynamically loads strategy by class path
  └── guards.py                   ← Enforces daily application limits

strategies/
  ├── base.py                     ← Abstract base class for all strategies
  └── custom/
      ├── wipro.py                ← Wipro (SAP UI5 — JS Shadow-DOM extraction)
      ├── infosys.py              ← Infosys BKS portal (full form automation)
      ├── lancesoft.py            ← LanceSoft / JobDiva portal
      ├── kforce.py               ← KForce (guest applications)
      ├── capgemini.py            ← Capgemini / SAP SuccessFactors
      ├── insight_global.py       ← Insight Global portal
      └── hiring_cafe.py          ← Hiring Cafe aggregator

core/
  ├── browser.py                  ← undetected-chromedriver lifecycle
  ├── human_behavior.py           ← Randomised delays, mouse movement, typing
  ├── safe_actions.py             ← Resilient click / fill with retry logic
  ├── candidate_loader.py         ← Merges parsed_resume.json + guest_form_data.json
  ├── captcha_handler.py          ← reCAPTCHA detection & manual solve prompt
  ├── config_manager.py           ← Env-var and .env config loader
  ├── proxy_manager.py            ← Optional proxy support
  └── logger.py                   ← Centralised logging setup

data/
  ├── db_connection.py            ← DuckDB singleton connection
  ├── db_duckdb.py                ← Schema creation & helper queries
  ├── guest_form_data.json        ← Candidate profile & search parameters
  ├── parsed_resume.json          ← Auto-generated by parse_resume.py
  └── job_engine.duckdb           ← Single local database file
```

## 🗄️ Database (DuckDB)

All config and tracking live in `data/job_engine.duckdb`.

### Configuration tables

| Table | Purpose |
|---|---|
| `ats_platforms` | ATS platform name, automation class path, automation level |
| `job_sites` | Company name, domain, search URL, daily application cap |
| `site_selectors` | Per-site CSS selectors stored as JSON (listing + application) |

### Tracking tables

| Table | Purpose |
|---|---|
| `applied_jobs` | Deduplication — prevents re-applying to the same job |
| `scheduler_runs` | Audit log for every automated run (timestamp, counts, errors) |

## 🚀 Quick Start

### 1. Install dependencies

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Configure environment

Copy `.env.example` → `.env`:

```env
DUCKDB_PATH=data/job_engine.duckdb
RESUME_FILE_PATH=resume/candidate_resume.pdf
HEADLESS=False
KEEP_BROWSER_OPEN=False

# Required for Capgemini only
CAPGEMINI_EMAIL=your@email.com
CAPGEMINI_PASSWORD=yourpassword
```

### 3. Configure your candidate profile

Edit `data/guest_form_data.json` — the single source of truth for all form-filling:

```jsonc
{
  "applicant": {
    "first_name": "Jane",
    "last_name": "Doe",
    "email": "jane@example.com",
    "phone": "5551234567",
    "linkedin_url": "https://linkedin.com/in/janedoe",
    "city": "Austin",
    "state": "Texas",
    "zip_code": "78701",
    "street_address": "123 Main St"
  },
  "search": {
    "keyword": "AI Engineer",
    "location": "United States"
  }
}
```

### 4. Parse your resume

```bash
python scripts/parse_resume.py
```

This reads `resume/candidate_resume.pdf` and writes `data/parsed_resume.json` with structured fields (GPA, field of study, work history, skills, etc.) that supplement `guest_form_data.json`.

### 5. Initialise the database

```bash
python scripts/init_db.py
```

Creates all tables and seeds site configs + selectors for all supported sites.

### 6. Run a site

```bash
# Active (scheduler) sites
python scripts/main.py --site "Wipro"
python scripts/main.py --site "Infosys"
python scripts/main.py --site "LanceSoft"

# On-demand sites
python scripts/main.py --site "Insight Global"
python scripts/main.py --site "KForce"
python scripts/main.py --site "Capgemini"
python scripts/main.py --site "Hiring Cafe"
```

Or use the included `.bat` shortcuts:

```bash
test_wipro.bat
test_infosys.bat
test_lancesoft.bat
test_kforce.bat
```

## ⚙️ Windows Task Scheduler (Automated Daily Runs)

`run_scheduler.bat` is designed to be triggered daily by Windows Task Scheduler.

```
run_scheduler.bat
  └── scheduler_worker.py
        └── loops over all is_active=true sites in sequence
              └── logs every run to scheduler_runs table in DuckDB
```

**Setup:**

1. Open **Task Scheduler** → *Create Task*
2. **General** → ✅ "Run with highest privileges"
3. **Triggers** → Daily at your preferred time
4. **Actions** → Start `run_scheduler.bat`; set *Start in* to the project root
5. **Conditions** → Uncheck "Start only if on AC power"

## 📦 Candidate Data Flow

```
resume/candidate_resume.pdf
        │
        ▼ (parse_resume.py)
data/parsed_resume.json         ← structured resume fields
data/guest_form_data.json       ← personal profile + search config
        │
        ▼ (core/candidate_loader.py)
        CandidateProfile        ← merged object used by all strategies
```

`candidate_loader.py` merges both files, with `parsed_resume.json` fields taking priority for resume-derived data (GPA, field of study, work history) and `guest_form_data.json` providing contact/search info.

## 🧠 How the Strategy Pattern Works

1. `runner.py` reads `job_sites` from DuckDB to get the strategy class path (e.g. `strategies.custom.WiproStrategy`).
2. `factory.py` dynamically imports and instantiates the strategy with the browser driver, site config, and DB session.
3. The strategy's `find_jobs()` method discovers job listings and returns a list of `{job_title, external_id, job_url}` dicts.
4. `runner.py` deduplicates results against `applied_jobs`, then calls `strategy.apply(listing)` for each new job.
5. Each successful application is written to `applied_jobs` to prevent re-application.

### Adding a new site

1. Create `strategies/custom/mysite.py` extending `strategies.base.BaseStrategy`.
2. Implement `login()`, `find_jobs()`, and `apply()`.
3. Insert a row into `job_sites` and `site_selectors` in DuckDB (add to `init_db.py`).
4. Run `python scripts/init_db.py` to populate, then test with `python scripts/main.py --site "MySite"`.
