# 🤖 Job Application Engine

A database-driven, multi-site job application automation engine built on the **Strategy Pattern**. Each job board has its own self-contained strategy module. Configuration, deduplication, and audit logging live in DuckDB (MotherDuck Cloud).

---

## 🏗️ Architecture

```
scripts/main.py                   ← Single-site manual entry point
scripts/scheduler_worker.py       ← Scheduled multi-site runner (API-driven)

engine/
  ├── runner.py                   ← Orchestrates browser + strategy per site
  ├── factory.py                  ← Dynamically loads strategy by class path
  └── guards.py                   ← Enforces daily application limits

strategies/
  ├── base.py                     ← Abstract base class for all strategies
  └── custom/
      ├── wipro.py                ← Wipro (SAP UI5 — JS Shadow-DOM extraction)
      ├── infosys.py              ← Infosys BKS portal (full form automation)
      ├── lancesoft.py            ← LanceSoft / JobDiva portal
      ├── kforce.py               ← KForce (guest applications)
      ├── capgemini.py            ← Capgemini / SAP SuccessFactors
      └── insight_global.py       ← Insight Global portal

core/
  ├── browser.py                  ← undetected-chromedriver lifecycle
  ├── human_behavior.py           ← Randomised delays, mouse movement, typing
  ├── safe_actions.py             ← Resilient click / fill with retry logic
  ├── candidate_loader.py         ← Merges parsed_resume.json + guest_form_data.json
  ├── captcha_handler.py          ← reCAPTCHA detection & manual solve prompt
  ├── config_manager.py           ← Env-var and .env config loader
  ├── proxy_manager.py            ← Optional proxy support
  └── logger.py                   ← Centralised logging setup

data/
  ├── db_connection.py            ← DuckDB singleton connection
  ├── db_duckdb.py                ← Schema creation & helper queries
  ├── guest_form_data.json        ← Fallback candidate profile & search parameters
  ├── parsed_resume.json          ← Auto-generated by parse_resume.py
  └── job_engine.duckdb           ← Local cache for DuckDB
```

## 🚀 Getting Started (For Teammates)

When pulling this code, you MUST complete these steps before the engine will run successfully:

### 1. Install dependencies

```bash
python -m venv venv
venv\Scripts\activate  # Windows
pip install -r requirements.txt
```

### 2. Configure environment (`.env`)

Copy `.env.example` → `.env` and fill in your details:

```env
HEADLESS=False
KEEP_BROWSER_OPEN=True

# Resume path
RESUME_FILE_PATH=resume/candidate_resume.pdf

# MotherDuck Database Configuration
DUCKDB_PATH=md:job_engine
MOTHERDUCK_TOKEN=your_motherduck_token_here

# Backend API Configuration
BACKEND_URL=http://localhost:8000

# Required for Capgemini only
CAPGEMINI_EMAIL=your@email.com
CAPGEMINI_PASSWORD=yourpassword
```

### 3. Ensure Backend API is Running

The `scheduler_worker.py` and tracking system relies heavily on the `wbl-backend` FastAPI server being active.
Ensure the backend is running on `http://localhost:8000` (or whatever your `BACKEND_URL` is set to).

### 4. Seed the Cloud Database

Because we use MotherDuck, you need to ensure the tables and selectors are seeded for your token/environment:

```bash
python scripts/init_db.py
python scripts/seed_wipro_selectors.py
```

### 5. Start the Engine!

**To test a single site manually:**
```bash
python scripts/main.py --site "LanceSoft"
```
*(Add `--dry-run` to test UI automation without actually clicking submit).*

**To run the fully automated multi-site API workflow:**
```bash
python scripts/scheduler_worker.py
```
*(This will fetch eligible candidates from the backend API, update their snapshot schedules, and apply to LanceSoft & KForce automatically).*
